# Playbook: Командный протокол (agent teams)

> Читают ВСЕ агенты и lead перед командной работой. Правки — только с апрува байера.
> Требует `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` (Claude Code ≥ 2.1.32).

## Статус
- ✅ **работает:** общий тасклист (TaskCreate/TaskList/TaskUpdate), прямые сообщения (SendMessage), спавн teammates из `.claude/agents/*.md` (frontmatter name/model/tools применяется).
- ⚠️ **грабли:** teammates наследуют права lead'а (изоляции прав пока нет — у qa «read-only» держится дисциплиной, не санкциями); ~7x токенов vs одиночная сессия — команду собирать только на пайплайн, не на разовые вопросы; идл-teammate жрёт токены; split-panes — только tmux/iTerm2 (иначе in-process режим).

## Роли
| Роль | Кто | Зона |
|---|---|---|
| **lead** (координатор) | главная сессия — общается с байером | декомпозиция, тасклист, спавн/shutdown teammates, синтез, эскалации |
| `syntx` | teammate (sonnet) | статика-креативы + ассеты PWA |
| `video` | teammate (opus) | видео: разведка Ad Library, ffmpeg-анализ, I2V-генерация |
| `adsetpro` | teammate (sonnet) | PWA + трекер-кампания |
| `fb` | teammate (opus) | залив, observer, Meta API |
| `qa` | teammate (opus) | ревью КАЖДОГО handoff + финала; вердикты, возврат на доработку |

Лимит: ≤ 5 фоновых агентов (правило CLAUDE.md) → lead + до 4 teammates одновременно. Спавнить только нужных этапу (напр., `video` и `adsetpro` обычно не нужны одновременно; завершённый этап → shutdown).

## Два режима работы
- **Одиночная задача** («перегенери CR003», «глянь метрики») — обычный вызов одного агента, команда НЕ нужна.
- **Пайплайн** (новый оффер/гео: креатив → PWA/трекер → залив) — team-режим. Запуск: байер говорит lead'у «собери команду на <оффер>» → lead раскладывает цепочку задач → спавнит teammates.

## Тасклист (общий)
- lead создаёт задачи ДО старта, с зависимостями (`addBlockedBy`) по цепочке:
  `syntx:креативы` → `qa:Gate A` → `adsetpro:PWA+трекер` → `qa:Gate B` → `fb:залив` → `qa:Gate C` → `lead:байеру`.
- **Видео-ветка** (вместо/вместе со статикой): `video:разведка` → [`syntx:статик-кадры` → `qa:Gate A` →] `video:I2V` → `qa:Gate AV` → `fb:залив` → `qa:Gate C`.
- Воркер: взял задачу → `in_progress` + owner; **`completed` — ТОЛЬКО после ✅ qa** (для гейтовых задач).
- Заблокирован → задача остаётся `in_progress`, создать задачу-блокер, сообщить lead'у. НЕ закрывать частично сделанное.

## Сообщения (SendMessage)
- **Handoff — напрямую следующему агенту** (lead не дублировать — он видит тасклист).
- Формат handoff: ЧТО сделано · ГДЕ артефакты (пути/папки/id/ссылки) · ЧТО получателю делать дальше · известные ограничения/грабли.
- Broadcast — только lead, только при смене вводных всей команды (оффер/гео/act_id/бонус).
- Вопросы денег/стратегии/go — НЕ соседу, а lead'у → байеру (см. Эскалация).

## Ревью-цикл (qa) — слой приёмки
Гейты и чеклисты — `review-gates.md`. Схема:

```
syntx ──креативы──▶ qa Gate A ──✅──▶ adsetpro ──PWA+ссылка──▶ qa Gate B ──✅──▶ fb ──PAUSED──▶ qa Gate C ──✅──▶ байер (unpause)
            ▲           │ ❌ REJECT (пункты)        ▲             │ ❌                  ▲          │ ❌
            └───────────┘                           └─────────────┘                    └──────────┘
```

- Видео-гейт: **Gate AV** (между Gate A и B; чеклист — `review-gates.md`, артефакты = mp4 + раскадровки).
- Воркер закончил этап → SendMessage `qa` с артефактами → ждёт вердикт.
- Вердикт qa: **✅ APPROVE** или **❌ REJECT + пронумерованные пункты**. REJECT → воркер правит ТОЛЬКО названные пункты (инварианты держать) → ре-ревью.
- **Лимит 3 итерации на гейт** → qa эскалирует lead'у → решение байера (принять как есть / сменить подход). Без бесконечного пинг-понга.
- qa сам НЕ правит и НЕ исполняет. Гейт qa — ДО байера, не вместо: финальное слово и деньги — всегда байер.

## Эскалация и деньги (не меняется team-режимом)
- Только байер (через lead): бюджет, стратегия, нейминг, выбор страницы, `act_id`, go на залив, unpause, ввод кредов.
- Несогласие воркера с вердиктом qa → lead → байер. Агенты между собой вердикты не «передоговаривают».

## Дисциплина
- teammate без задач → lead делает shutdown, идл не держать.
- Каждый teammate ПЕРЕД работой читает СВОЙ playbook (как и вне команды) — team-режим этого не отменяет.
- Правки playbooks — по-прежнему diff → апрув байера (governance `README.md`).

## Связанное
- Гейты/чеклисты ревью — `review-gates.md`. Карта агент→playbook — `README.md`.
