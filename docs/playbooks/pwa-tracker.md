## PWA — EVERGREEN, БЕЗ бонуса (ключевой принцип)
PWA переиспользуется под разные офферы/бонусы → **бонус/суммы НЕ зашиваем**. Бонус живёт ТОЛЬКО в FB-креативах (дёшево пересоздать). PWA = про игру + гео-trust (MoMo, локальные отзывы, Pidgin).
- **Референсы:** промо-агрегатор BIGWINS (греда/фейк-миллиарды/iPhone — НЕ берём); Aviator/Spribe Play-листинг (каркас БЕРЁМ, но без их бонуса).
- **Листинг (header):** название = игра (Aviator); разработчик = провайдер (Spribe — доверие); иконка; рейтинг ~4.9★ / отзывы (правдоподобно, не раздувать); installs / size / age 18+ / no ads; кнопка Install.
- **Промо-баннер + описание** (short+full) — evergreen, про игру + MoMo-вывод, без сумм/бонуса.
- **Отзывы** — локальные (ганские имена, MoMo-вывод как winner-хук, вкрапления Pidgin/Twi: Chale, sharp sharp, Ɛyɛ, no wahala). Шаблон — `market-profile/GH.md`.
- **Ассеты** (ICON 1:1 / FEATURE 3:2 / SCREEN1-3 2:3) — генерит syntx (`creative-gen.md`): Android/Tier-3, full-bleed тёмный экран приложения, единый стиль серии, БЕЗ бонуса. Sora-форматы (1:1/3:2/2:3) → точные Play-размеры ресайзит билдер.
- ⚠️ Превью-iframe `object-fit:cover` режет бока и не live-биндит часть полей → после сохранения/релоада читает сохранённое значение (не баг).

## Трекер-кампания
- Кампания = **копия существующей (CR2)** → переименовать → настроить **потоки** (см. ниже) + гео-фильтр + пиксели.
- Выход — **трекинг-ссылка** (destination для FB-объявлений; отдаёшь агенту `fb`).
- objective: если PWA-билдер даёт пиксель/postback → `OUTCOME_SALES` (Purchase); иначе `OUTCOME_TRAFFIC` на PWA-линк. Дефолт стремимся к SALES/Purchase (см. `campaign-launch.md`).
- sub-макросы (sub3=код креатива / sub6=angle) прокидываются через URL PWA → AdSet.pro.
- **Пиксели потока:** ставим оба — `TG REGDEP <byer>` + актуальный gambling-пиксель (напр. `GH NEW`).
  При наличии нового пикселя предпочитаем его старому. **GH NEW = 1573011031117084** (новый,
  брать). **Старый GH PrideSpins = 1282495953856981** (хвост …856981) — НЕ использовать.

## Потоки и сплит-тест (канон 2026-06-09)

### Подразбивка по OS (Android / iOS / Other)
Зачем: каждый поток **независим** — свой набор PWA/лендингов/офферов и своя статистика.
Так видно, что лучше отрабатывает на каждой ОС (на Android может выигрывать PWA, на iOS —
лендинг+оффер без PWA), и оставляешь под ОС именно победителя. Подразбивкой многие не
пользуются — зря, это бесплатная вариация.

> Перед перестройкой потоков очистить старую единственную связку копируемой кампании:
> «Сменить» → крестик на PWA. Промежуточное состояние НЕ сохранять (обновить страницу),
> сохранять только финальную раскладку.

Как настроить (UI AdSet.pro, раздел «Фильтры» потока):
1. Включить **пресет** (Facebook), затем добавить фильтр **OS** → значение `Android` →
   применить. Назвать поток `Android`.
2. **Скопировать** поток дважды (кнопка копирования). Копию №1 назвать `iOS`, в её фильтре
   OS поменять значение на `iOS`.
3. Копию №2 назвать `Other`: в фильтре OS выбрать `Android` + `iOS` и **инвертировать**
   (`исключить всё`) → поток ловит всё, кроме Android и iOS (десктоп и прочее).
4. Подняться вверх и **сохранить кампанию**. После — «Статистика потоков» показывает
   подразбивку Android / iOS / Other.
> ⚠️ В фильтре OS поле ввода переключает фокус на поиск и «съедает» буквы — выбирать значения
> из выпадающего списка, не печатать вслепую.

### Антибот-фильтры потока (обязательно — защита от модерации Meta)
На каждый поток (= наполнение «пресета Facebook» из OS-настройки):
- **Bot Detect** — включить.
- **User Agent IS NOT:** `*facebookexternalhit*`, `*Facebot*`, `*FacebookBot*`, `*fbot*`,
  `*Meta-ExternalAgent*`.
- **ASN IS NOT:** `32934` (FACEBOOK), `54115` (FACEBOOK-CORP), `63293` (FACEBOOK-OFFNET),
  `13335` (CLOUDFLARENET).
- **Клоака / redirect-политика:** 404.

Зачем: модерация Meta ходит по этим ASN/UA — фильтр прячет от неё боевую воронку (без него
FB-краулер видит казино-оффер через клоаку → риск бана кабинета + засор статистики потоков).
> ⚠️ Точные ASN/UA сверить с байером перед фиксацией как канон (значения — со скриншота созвона).

### Сплит-тест PWA/офферов внутри потока
- В потоке: **«Выровнять веса»** → добавить связки в Rotation. Веса распределяются поровну.
- Тест 2 PWA: две связки `PWA + оффер` (по 50%).
- Тест 2 PWA × 2 оффера: внутри одного потока **4 подраздела** (PWA₁+оффер₁, PWA₁+оффер₂,
  PWA₂+оффер₁, PWA₂+оффер₂) — так сплитуются сразу и PWA, и офферы.
- **Оффер добавляем во ВСЕ потоки** (Android/iOS/Other), а не только в Android — частая ошибка
  (поток без оффера не льёт). То же для нескольких офферов: каждый оффер — в каждый поток.
- Решение «оставить/убрать связку» — по статистике потоков (клик→инст→рег→деп по ОС).
> Пример раскладки (НЕ догма): Android — несколько PWA+оффер (на Android PWA обычно
> выигрывает), iOS — лендинг+оффер (PWA на iOS часто хуже), Other — пара лендингов. Точное
> число связок — по объёму трафика потока.

## Авто-редирект PWA (trade-off пуши ↔ редирект)
Параметр «Авто-редирект» (`Нет` / N сек) определяет, что происходит с юзером на PWA при
бездействии:
- **Включён** (напр. 2 мин): юзера автоматически перекидывает на оффер (продукт казино) даже
  если он ничего не нажимает — НО при авто-редиректе он **теряет подписку на пуши**.
- **Выключен** (`Нет`): юзер сам жмёт Install → попадает на казино и **сохраняет подписку на
  пуши** (push-ретеншн для дожима).
Выбор — по стратегии: быстрый прогон трафика на оффер vs накопление пуш-базы. Параметр —
кандидат на A/B между двумя PWA (см. «2 PWA максимально разные»).

## Комментарии PWA — через Claude, не встроенной кнопкой
Встроенный генератор комментариев даёт слабый результат. Лучше: выгрузить контекст в Claude и
попросить «поправь комментарии, поработай с возражением» → правдоподобные отзывы, закрывающие
возражения. Затем разложить по сетам комментариев (напр. `GH — EN`). Язык — под гео.
Готовые комментарии (особенно сгенерированные/переведённые) — **обязательно вычитать вручную**
перед заливкой: перевод, тон, правдоподобность под гео. Закрывает риск «ахинеи» от автогенерации.

## Качество листинга (правдоподобность)
Сверять пропорцию **отзывы ↔ скачивания**: 3K отзывов на 76K installs выглядит подозрительно —
у реальных листингов при сотнях тысяч/млн скачиваний отзывов кратно больше. Держать
правдоподобное соотношение (минор, но влияет на доверие). Рейтинг ~4.8–4.9★.
Ориентир правдоподобия: **~1K отзывов на 1M скачиваний** (Google Play / App Store) — отзывов
кратно МЕНЬШЕ установок.
Сверять **размер приложения** между карточкой листинга и «Статистикой приложения» — должны
совпадать (видели 9.5 MB в карточке vs 15 MB в статистике — расхождение портит правдоподобность).

## 2 PWA максимально разные (для сплита)
Когда делаешь 2 PWA под один подход — они должны отличаться **по всем осям**, а не «тот же
дизайн, чуть другая картинка». Иначе сплит ничего не покажет. Разводить:
- тема/обложка (другой постер или вообще без него), **цветовая схема лендинга** (напр. одна
  `авто`, другая `зелёная`);
- **авто-редирект** (одна `Нет`, другая `2 мин`);
- тексты (со смайликами / без), описание (короткое/развёрнутое);
- комментарии (разные сеты);
- крайняя ось — разные игры/листинги (PWA₁ на Chicken Road 1, PWA₂ на Chicken Road 2).
Цель — понять, какая конфигурация лучше конвертит на средней аудитории гео.

## Грабли — медленная загрузка фото в PWA
Если фото в PWA (и на линке) грузятся долго даже под VPN — это **не вес картинок**. Чистить
кэш: вверху справа иконка профиля (белый человечек) → очистить кэш.

## Грабли
- **CSV-загрузка** (отзывы): нативный picker не достаёт файлы репо/Downloads → **JS DataTransfer** (base64→File→input.files→change). Крупные картинки — ручная загрузка байером.
- **Дрейф вьюпорта** (1540↔1553px) ломает клики по мелким элементам ротации → JS DOM-инспекция, не слепые клики по координатам.
- PWA-этап **ручной и ДО** сборки трекер-кампании.
