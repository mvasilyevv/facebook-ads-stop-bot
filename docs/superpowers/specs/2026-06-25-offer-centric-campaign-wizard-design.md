# Offer-centric визард создания кампаний — дизайн

Дата: 2026-06-25. Статус: утверждён (устно), к реализации по фазам.

## Проблема

Визард создания кампаний требует много ручного ввода, часть полей — свободный текст
(`objective`, `optimization_goal`, `custom_event_type`, `pixel_id` руками), что даёт
невалидные связки → кампания не создаётся в Meta. Цель: **минимум ручного ввода**;
конфигурация строится из (а) выбранного **оффера** (единый источник правды), (б)
**валидных опций FB** (дропдауны вместо free-text), (в) проверки реальным **Meta
`validate_only`** перед заливом.

## Подход

Расширяем существующую сущность **Offer** (она уже держит `ad_account_ids` + `pixel_id`),
а не вводим новую config-сущность. Страница — гибрид: дропдаун-фетч из кабинета
(`/act_{id}/promote_pages`, уже реализован) + дефолт на оффере для преселекта.

## Границы (что куда)

- **На Offer** (настроил раз → визард подставляет): `ad_account_ids` (есть),
  `pixel_id` (есть), 🆕 `countries` (ISO-2 список, гео оффера/мультигео),
  🆕 `default_page_id` (обычная страница оффера, опц.).
- **Глобальный дефолт по SOP** (не per-offer, валидные дропдауны):
  `OUTCOME_SALES / OFFSITE_CONVERSIONS / PURCHASE`, CTA из валидного enum.
- **Per-launch**: дата старта, бюджет, структура (фото/видео × N), концепты,
  выбор кабинета (если у оффера их несколько), правки любого подставленного поля.

## Данные / миграция

Alembic: в таблицу `offers` добавить:
- `countries` — `JSONB`/`ARRAY(text)`, дефолт `[]` (как `ad_account_ids`).
- `default_page_id` — `text NULL`.

Модель `core/models/catalog/offer.py`, схемы `OfferOut/OfferCreateIn/OfferUpdateIn`,
роутер `offers.py`, форма `OfferFormModal` (web) — принимают/отдают новые поля.
Гео — мульти-тег-инпут (TagListInput, ISO-2 upper). Мини-фронт офферов — если есть.

## Поток визарда (offer-driven)

Шаг «Идентичность» переориентируется на выбор оффера:
1. Выбор **оффера** из каталога (дропдаун; offer_code-комбобокс уже есть).
2. На выбор оффера → дерайв в стор:
   - **Кабинет**: `offer.ad_account_ids` — 1 → авто; >1 → дропдаун выбора кабинета.
   - **Пиксель**: `offer.pixel_id` → префилл `pixel_id`.
   - **TZ**: авто-фетч по выбранному кабинету (реализовано) + гард подтверждения.
   - **Страница**: дропдаун из кабинета (реализовано), преселект `offer.default_page_id`.
   - **Гео**: `offer.countries` → префилл `countries` в шаге «Параметры».
3. Все подставленные поля **редактируемы** (оффер = дефолт, не замок).

Мультигео: `offer.countries` идут в таргет одного adset
(`geo_locations.countries = [...]`) — без сплита по странам (канон гемблинг-мультика).

## Валидные enum-дропдауны (шаг «Параметры»)

`objective / optimization_goal / custom_event_type / CTA` — `Select` с валидными
значениями FB вместо free-text. Дефолт — гемблинг-связка по SOP. Список значений и
связка валидности (objective → допустимые optimization_goal/event) зашиваются как
константы (как делает сам UI FB — отдельного «дай валидные опции» API у Meta нет).
`bid_strategy`/атрибуция уже дропдауны.

## Pre-flight `validate_only`

Перед заливом гоняем полный конфиг кампании через Meta create-call с
`execution_options=['validate_only']` — Meta валидирует по реальным правилам и
возвращает ошибки БЕЗ создания объектов. Расширяет текущий dry-run `/validate`
(сейчас проверяет только план билдера, не FB). Канал — тот же
`MetaApiClient.execute_graph_call` через Vision-сессию (money-safe, read-only по
эффекту: объекты не создаются).

## Фазы (независимые, по порядку)

| Фаза | Состав | Ценность |
|---|---|---|
| **1** | Offer-поля (`countries`, `default_page_id`) + миграция + модель/схемы/роутер + форма офферов + дерайв в визарде (кабинет-пик, префилл пиксель/гео/страница) | ноль ручного ввода — ядро |
| **2** | Валидные enum-дропдауны (objective/opt/event/CTA) + связка валидности + гемблинг-дефолт | убирает кривые связки |
| **3** | `validate_only` pre-flight (бэк-эндпоинт + шаг превью показывает вердикт FB) | гарантия приёма Meta |

## Тестирование

- Unit/семантика: дерайв из оффера (1 vs N кабинетов), пустой `countries`, миграция
  обратима, enum-дропдауны дефолтят корректно, `validate_only` маппит ошибки FB.
- Фронт: vitest web+mini, tsc strict; money-инвариант `buildConfig` (preview==execute)
  не ломается; гард подтверждения TZ остаётся.
- НЕ запускать integration на живой :5433 (стирает offers).

## Риски / открытые

- FB enum-матрица валидности зашита константами — при изменениях Meta обновлять руками
  (как и сам UI FB).
- Мультикабинет UX: если у оффера много кабинетов — дропдаун выбора на залив (не фан-аут).
- `default_page_id` оффера может не быть среди promote_pages кабинета → дропдаун покажет
  фетч-список, дефолт не преселектится (не блок, ручной выбор).
