# Roadmap: полный функционал управления сканом в UI

Зафиксировано 2026-06-19. Домен: observer + frontend (НЕ TG-волны — отдельный трек).

## Что уже есть (Dashboard, ScanCluster)
- **Сканировать** → `POST /settings/observer/scan-now` (немедленный скан).
- **Выключить** → `PATCH /settings/observer/scanning {enabled:false}` (стоп мониторинга, действует со след. цикла).
- **Включить** → `PATCH .../scanning {enabled:true}`.

## Пробел (этот пункт)
1. **Прервать УЖЕ идущий скан-цикл.** Сейчас во время скана кнопка «Сканировать» становится `disabled`
   (спиннер «Сканирую»), а прервать текущий цикл нельзя. «Выключить» останавливает только МОНИТОРИНГ
   (со следующего цикла), не текущий проход.
   - Нужно: `POST /observer/abort-scan` (publish Redis-сигнал, напр. `fb_agent:observer:abort`) +
     обработка в `observer_worker` (прервать текущий gRPC `RunScanCycle` / не добивать остаток
     кабинетов в мульти-кабинетном цикле) + кнопка в `ScanCluster` (во время `scanning` →
     «Прервать» вместо disabled-спиннера).
   - Сложность: прерывание идущего gRPC-стрима к browser-agent нетривиально — вероятно «мягкое»
     прерывание (отменить остаток цикла на границе кабинета/строки, не убивать gRPC силой).
2. **`POST /observer/restart`** есть в бэке, но не выведен в шапку Dashboard — добавить кнопку
   «Рестарт observer» (в ScanCluster или Settings/Observer).

## Приоритет
Backlog. Не money-критично (мониторинг можно выключить штатно). Делать отдельным треком после
TG-волн, либо когда руки дойдут до UI-полировки observer-контролов.
