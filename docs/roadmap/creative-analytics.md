# Креативная аналитика — Roadmap

Расширение FB Stop Bot до полноценного сервиса креативной аналитики. Сейчас система умеет вести кампании (мониторинг, стоп-правила, отключение/включение объявлений). Следующий уровень — анализ креативов: почему одни объявления конвертят лучше других, какие хуки работают, какие гипотезы тестировать дальше.

Документ фиксирует идею, архитектурный набросок, результаты выбора LLM-моделей и план поэтапной реализации.

---

## 1. Идея и зачем

Арбитраж — это не только ведение кампаний, но и работа с креативами: визуал, текст, хуки, тестирование подходов. Сейчас весь анализ результатов делается вручную: байер смотрит метрики, сравнивает креативы, формулирует гипотезы для следующего теста.

Цель — автоматизировать этот цикл:
- хранить все креативы (изображения + извлечённый текст) с привязкой к объявлениям;
- агрегировать метрики по креативам (CTR, CR рег→деп, CPL, spend);
- через внешние LLM/VLM анализировать топ/боттом креативы, находить отличия в хуке, тексте, визуале;
- генерировать конкретные гипотезы для следующих тестов и слать дайджесты в Telegram.

## 2. Архитектурный набросок

### 2.1 Новые сущности БД

- **`Creative`** — физический файл в папке: путь, perceptual hash (для дедупа после уникализации), извлечённый текст (OCR для статики, транскрипция Whisper + первый кадр для видео), теги (хук, оффер, гео), эмбеддинги изображения и текста.
- **`CreativeUsage`** — связь `Creative ↔ fb_ad_id`. Один исходник после уникализации даёт N объявлений; нужно знать, какой Ad из какого мастер-креатива растёт.
- **`CreativeInsight`** — результат анализа от LLM: что общего у топ-N, какие гипотезы для следующего теста, что отличает плохие.

### 2.2 Новые воркеры

- **`creative_indexer_worker`** — следит за папкой с креативами (или принимает путь при создании кампании в UI). Считает хеши, извлекает текст (OCR / Whisper), сохраняет `Creative`. Матчит с `AdSnapshot` по hash изображения или паттерну имени файла.
- **`creative_analyst_worker`** — берёт оффер с ≥ 10 объявлениями, делит на top/bottom по CR (или CPL), отправляет пачку в LLM-провайдера, сохраняет `CreativeInsight`, шлёт в Telegram дайджест.

### 2.3 Интеграция с существующим кодом

- Текущие воркеры (observer / disable / enable / recommendation) не трогаем.
- FastAPI — добавить роуты `GET/POST /api/creatives`, `GET /api/offers/{id}/insights`.
- UI — на странице оффера добавить блок «Креативы» и «Инсайты». При создании кампании — поле «Папка с креативами».

## 3. Выбор внешних моделей — результаты теста

### 3.1 Контекст проблемы

Главная боль — политика провайдеров по i-gaming. Большие провайдеры (OpenAI, Anthropic, Google) формально классифицируют gambling как ограниченную / YMYL-категорию. Часть моделей режут запросы про депозиты, бонусы, payment proof. У команды есть все согласования с Meta на gambling, но автоматизированный пайплайн должен пробивать политику программно через корректный system prompt.

### 3.2 Методология теста

Слепой тест: один и тот же промт (system + task) отправлен в 5 разных моделей. Промт лежит в `docs/roadmap/creative-analytics.prompt.md`. Кейс: два креатива iGaming-оффера в Бразилии (Fortune Tiger / Tigrinho, PIX-вывод) с метриками, нужно объяснить разницу, предложить 3 теста, перечислить риски.

Оси оценки:
- прошёл ли политику (бинарный фильтр);
- глубина арбитража (понимает ли хуки, психологию холодного трафика, разницу CR рег→деп vs CTR);
- гео-специфика (Tigrinho, PIX, локальные регуляторы, Tier-2/3 поведение);
- конкретность тестов и рисков;
- культурные / нишевые инсайты.

### 3.3 Результаты по моделям (май 2026)

| Модель | Политика | Сильные стороны | Слабости |
|---|---|---|---|
| **GPT-5.5** | прошёл с APPROVED CONTEXT | самая глубокая performance-аналитика (soft CTA, кривая выгорания Day 1-2 → Day 4-7) | дороже DeepSeek в ~30× на output |
| **Claude Opus 4.7** | **отказ** | этичная мотивация отказа (фабрикация winner-историй) | не подходит для этой задачи |
| **DeepSeek V4 (обычный)** | прошёл | лучший operational execution: обход модерации Meta, post-click consistency лендинга, гео-разница между штатами | менее яркие культурные инсайты |
| **DeepSeek V4 (thinking)** | прошёл | бизнес-уровень: SMS Nubank как пруф, LTV-хантеры, риск инфополя | более ровный, без острых углов |
| **GLM 5** | прошёл | уникальные BR-инсайты: Horário Pagante, utility-angle | устаревает на фоне 5.1 |
| **GLM 5.1 (обычный)** | прошёл | локальная фактура: Ministério da Fazenda, KYC / wager x50 риски, бытовые сравнения (R$1 = автобусный билет) | — |
| **GLM 5.1 (deep research)** | прошёл | operational механики: `Sinais Tigrinho` WhatsApp-группы, конкретные альтернативы слотам (Fortune Ox / Jogo do Boi), 3-шаговый гайд-формат креатива | — |

### 3.4 Финальный шорт-лист

| Слой пайплайна | Модель | Обоснование |
|---|---|---|
| Бэкбон / дефолт | **DeepSeek V4-Flash** | дёшево (1M контекст, MIT, ~$0.87/$25 на output против $25/$125 у GPT-5.5), мягкая политика, ровный operational output |
| Глубокая аналитика хука | **GPT-5.5** | подключать только когда DeepSeek даёт «ровный, но плоский» ответ — арбитр и углубление |
| Culture / locale layer | **GLM 5.1 (обычный)** | знание локальных регуляторов, бытовая фактура, культурные коды |
| Operational механики креативов | **GLM 5.1 (deep research)** | генерация конкретных hook-форматов, альтернативы слотам при выгорании |
| Не используем | Claude (Opus / Sonnet) | отказывает на этой задаче; оставляем для code review, дебага, документации |
| Vision (не протестировано) | Qwen3-VL / Pixtral Large / Gemini 3 Pro Vision | требует отдельного теста на реальных изображениях |

### 3.5 Прагматичная связка

На каждом цикле анализа оффера:
1. Основной анализ — DeepSeek V4-Flash (обычный).
2. Culture-уточнение — GLM 5.1 (обычный).
3. Если выводы расходятся в ключевых пунктах — арбитр GPT-5.5.

Это даёт покрытие по трём осям (operational / культурный / глубинный) и держит стоимость под контролем за счёт дешёвого бэкбона.

## 4. Roadmap

### Фаза 1. Хранение креативов (1-2 недели)
- модели `Creative`, `CreativeUsage`, миграция;
- `creative_indexer_worker` с поддержкой OCR (Tesseract / EasyOCR) и Whisper для видео;
- UI на странице оффера: список креативов, превью, привязка к Ad'ам;
- API-роуты для CRUD.

Без анализа. База, без которой инсайты некуда складывать.

### Фаза 2. Абстракция LLM-клиента (параллельно, 3-5 дней)
- интерфейс `LLMClient` с реализациями: `DeepSeekClient`, `GPT55Client`, `GLM51Client`;
- единая конфигурация в `.env` (API-ключи, модели, лимиты);
- retry / fallback / логирование стоимости в БД (новая таблица `LLMUsage`);
- eval-харнесс для повторных слепых тестов при выходе новых версий.

### Фаза 3. Аналитический воркер (1-2 недели)
- `creative_analyst_worker`: цикл по офферам с N+ объявлений, top/bottom split по CR, отправка в DeepSeek + GLM 5.1, сохранение `CreativeInsight`;
- Telegram-дайджест в существующий канал по оффер-ID;
- расписание (раз в сутки / по триггеру).

### Фаза 4. Vision-тест и интеграция (1 неделя)
- слепой тест Qwen3-VL / Pixtral Large / Gemini 3 Pro Vision на 20-30 реальных пар креативов;
- выбор vision-модели, добавление в LLM-абстракцию;
- анализатор смотрит на сам визуал, а не только на извлечённый OCR-текст.

### Фаза 5. Расширения (после MVP)
- генерация конкретных гипотез для следующего теста (заголовки PT-BR + RU, описание визуала);
- поиск похожих креативов в библиотеке по эмбеддингам;
- автоматический A/B-план с оценкой ожидаемого CTR/CR;
- интеграция со связкой `creator_worker` (если есть) — автогенерация уникализированных вариаций.

## 5. Открытые вопросы / решения на потом

- **Цена на реальной нагрузке.** Один запрос — $0.001-0.05. На N офферов × M раз в день экономика меняется. Посчитать перед запуском воркера в прод.
- **Какой OCR для статики и видео?** Tesseract бесплатный, но качество среднее. EasyOCR / PaddleOCR лучше. Whisper для видео — точно стоит, но нужна машина с GPU или API.
- **Где хранить файлы креативов?** Сейчас они в папке у байера. Нужна ли централизация (S3 / MinIO)? Зависит от объёма и multi-user сценария.
- **Vision: API или self-host?** Qwen3-VL и Pixtral доступны через API (Alibaba, OpenRouter, Fireworks, Mistral). Self-host для IP-защиты, но требует GPU. Решить на фазе 4.
- **Привязка `Creative ↔ fb_ad_id` после уникализации.** Если уникализатор оставляет паттерн в имени файла или метаданных — матчим напрямую. Если нет — нужен perceptual hash и hashing уже на скачанных превью объявлений.
- **GLM 5.1 vs 5.2 / новые версии.** Z.AI релизит быстро, eval-харнесс должен переоценивать модели при выходе новых версий.
