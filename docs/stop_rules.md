# Стоп-правила — reference (подтверждено владельцем 2026-05-29)

> Источник правды по стоп-логике. Движок: `core/rules/evaluator.py` + `core/rules/types.py` (`RuleContext`).
> Контекст собирается в `core/observer/pipeline.py::build_rule_context`. Калибровка проверена на живом заливе CR2 (GH/KE).

## Модель оффера и гео

- Оффер матчится по коду в названии (`core/observer/queries.py::match_offer_for_ad`): приоритет **ad_name** над campaign_name, выигрывает **самый длинный** код.
- **Гео-различение через отдельные офферы.** У одного продукта (CR2) разный CPA по странам → заводим отдельные офферы с гео-префиксом:
  - `KE_CR2` — CPA **$8** (Kenya)
  - `GH_CR2` — CPA **$3** (Ghana)
- Работает, потому что объявления названы слитно через `_`: `KE_CR2_CR005`, `GH_CR2_CR001`. Код `KE_CR2` (word-boundary) матчит ad_name и длиннее `CR2` → выигрывает. В названии кампании (`MV | KE | CR2`) гео и код разделены ` | `, там `KE_CR2` не сматчился бы — поэтому ставка на ad_name.
- **Owner-scoping:** `observer_config.owner_campaign_tag` (напр. `MV`). Кампании без тега (word-boundary) полностью игнорируются. См. `campaign_matches_owner`.

## Свёртка порогов (двухуровневая)

Для каждой метрики (CPC/CPL/CPR):
```
база    = CPA × percent%            (percent: CPC 2%, CPL 10%, CPR 20%)
STOP    = база × 80%                (stop_percent_of_base = 80)
WARNING = STOP × 80%                (warning_percent_of_stop = 80)
```
Смысл: стоп срабатывает на 80% «правила» (буфер против перекрута), warning — за 80% до стопа.

### Готовые пороги

| Метрика | % CPA | **GH_CR2 (CPA $3)** | **KE_CR2 (CPA $8)** |
|---|---|---|---|
| CPC | 2% | база $0.06 · **STOP $0.048** · WARN $0.038 | база $0.16 · **STOP $0.128** · WARN $0.102 |
| CPL | 10% | база $0.30 · **STOP $0.24** · WARN $0.192 | база $0.80 · **STOP $0.64** · WARN $0.512 |
| CPR | 20% | база $0.60 · **STOP $0.48** · WARN $0.384 | база $1.60 · **STOP $1.28** · WARN $1.024 |

## 6 правил (+ 7-е независимое)

Движок идёт по воронке **показы → клики → лиды → реги → депозиты** и оценивает по самому глубокому достигнутому уровню:

1. **CPC** (клик-уровень): цена клика ≥ STOP-порога → стоп. Срабатывает сразу, **без ожидания объёма** (хоть 1 клик).
2. **CPL** (лид-уровень): цена лида ≥ STOP-порога → стоп.
3. **CPR** (рега-уровень): цена реги ≥ STOP-порога → стоп.
4. **regs_no_dep**: ≥5 регистраций и 0 депозитов → стоп (WARNING при 4 = ceil(5×0.8)).
5. **spend_no_dep_range**: расход 50–70% CPA, депозитов 0, цена реги в норме → стоп (с ×80% эффективно **40–56%**).
6. **spend_with_dep_range**: есть депозит, расход 70–90% CPA → стоп (эффективно **56–72%**).
7. **frequency_anomaly** (задел): frequency > 3.5 → стоп, > 2.5 + рост → warning. **Сейчас не активно** — `build_rule_context` не передаёт `frequency_current` (нужна доработка, если потребуется).

## Ключевая семантика (подтверждено владельцем)

- **Метрика ИЛИ сумма затрат.** На каждом уровне воронки, помимо метрики-за-единицу, работает **guardrail по сумме затрат**: «потрачено больше стоимости следующего события, а события нет → стоп». Примеры:
  - кликов 0, но spend > порога → стоп;
  - 5 кликов, CPC в норме, но spend > цены 1 лида без лидов → стоп.
- **Никакого ожидания объёма.** Правила срабатывают сразу при достижении порога — не ждём N кликов / лидов / рег. (Единственный sanity — `guardrail_min_impressions=10`: при <10 показов 1-2 показа не дают ложный guardrail; метрики при наличии события судятся всегда.)
- **WARNING → STOP** — двухуровнево: сначала предупреждение (алерт без отключения) на 80% стопа, затем STOP (алерт + disable-задача).

## Где настраивается

- CPA — `offer_rules.cpa_threshold` (per-оффер).
- Проценты/свёртка/диапазоны — дефолты `RuleContext` (глобальные, `core/rules/types.py`); `build_rule_context` пробрасывает только `cpa_amount` + свёртку 80/80. Per-offer override процентов сейчас не вынесен (все офферы делят дефолты, меняется только CPA).
- owner-тег — `observer_config.owner_campaign_tag` (API `PUT /settings/observer`).
