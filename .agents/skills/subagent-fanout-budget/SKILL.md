# Бюджет фан-аута субагентов

Параллельные субагенты ломаются так, что это видно только после того, как деньги потрачены:
каждый работает минутами, сжигает 130–260k токенов, а потом умирает на лимите **вывода** в 64k,
возвращая свой JSON, — теряется весь прогон, а не последний кусок.

## До запуска

Назвать три числа одной строкой:

```
N агентов × ~<токенов> ≈ <итого>; по времени ≈ <минут>
```

Больше ~500k суммарно или больше ~10 минут по времени — сначала спросить. Владелец, который
прерывает фан-аут на середине, уже заплатил за каждого запущенного агента.

## Контракт вывода: писать в файл, а не возвращать

Ответ субагента должен лечь на диск, а его финальное сообщение быть распиской, а не полезной
нагрузкой.

```
Запиши JSON в <абсолютный-путь>/chunk_NN.json.
Ответь ровно одной строкой: "<нод> нод, <рёбер> рёбер -> chunk_NN.json".
JSON в ответ не вставляй.
```

Причина: лимит 64k действует на ответ, а не на файл. Одно это правило превращает полную
потерю в возобновляемый шаг и делает повторы дешёвыми — готовые чанки уже на диске.

## Размер чанка

- Резать так, чтобы ожидаемый вывод одного агента был заметно ниже лимита; чанк умер по
  размеру — делить пополам и перезапускать только его (`list_05a` / `list_05b`), не весь набор.
- Перед любым перезапуском смотреть, что уже легло:

  ```bash
  ls -la <out>/chunk_*.json
  ```

- Две волны по N лучше одной волны на 2N: первая волна показывает реальную цену агента.

## Гигиена корпуса

Фильтровать вход до нарезки. Медиа, артефакты сборки и вендорные ассеты раздувают число
чанков и тянут за собой транскрипцию, которой никто не просил, — выкинуть и назвать, что
именно выкинуто, с числами.
